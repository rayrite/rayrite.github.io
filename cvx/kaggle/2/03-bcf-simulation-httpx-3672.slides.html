What this walkthrough does not prove

≈ Both trajectories are [SIM] — constructed, grounded in verified artifacts, zero receipts. Turn counts are design targets. This deck is a teaching example and a prompt few-shot, never a result.
  • A lucky naive roll passes. Keep the rename and migrate the visible tests (edits Container B discards anyway), or alias reset = complete — the graded suite accepts both. The failure shown is the modal trajectory the failure codebook predicts, not a certainty.
  • BCF can misroute. The classifier's feature signal is real ("Add …"); template choice is a judgment call. Spec-first is a hypothesis until the paired experiment runs.
  • One task. httpx is 1 of 129; a single-roll story on n=1 proves nothing about the other 128 — least of all the fastapi/rich multi-fault tasks where fault-masking actually chains.
  • The replacement is already scheduled: Config 1 / 2 / 3 paired runs on the frozen 30-task set, seeds {0,1,2} (Sprints 1–3) — that converts slides 5–7 from [SIM] to [M].

Pre-registered prediction #9 (candidate)

On rename/refactor tasks where the visible suite still targets the old API, Config 1 fails by test_misread (reverting correct fixes) at a higher rate than Config 3, whose spec carries the issue-text contract past the local signal. Mechanism: trap 1, which exists in the data regardless of agent design. Measured by failure_code distribution on the taxonomy's compat_or_refactor slice.
