These are the only execution-related numbers the package publishes. Everything to their right on this slide is assumption.

[EST]Assumptions — stated, replaceable, falsifiable

  • A1 · model turn: 15–45 s per turn for a mid-size agentic model with growing context (10–100k tokens). The dominant cost everywhere.
  • A2 · local tools: read / edit / write / search / graph resolve in < 1 s — they run in-container.
  • A3 · pytest: 3–15 s per run on this small, pure-Python suite (24 tests, collection + imports).
  • A4 · repro script: 1–3 s to execute.
  • Formula: step duration = Σ over its calls of (A1 turn + tool exec). Worst case per call ≈ 60 s — under the 72 s allowance.
± No public execution data exists for this harness as of 2026-10-01, and importing latency numbers from other agents/benchmarks would be false provenance — so every duration here is an [EST] built from the anchors and assumptions above. The Sprint 1–3 measured runs replace each one with [M]. If real turns average > 45 s or pytest runs cold, the totals shift up but stay inside 60 min at 24 calls.

Beforethe moment of maximum danger

Receipts, tiers, and what would change the answer

The three tiers, one last time

  • [V] — verified: tool schemas and budgets (HARNESS_README §6–7), the two-container lifecycle and anti-tamper reset (§8.2), graph node ids, the snapshot's traps, the gold and test patches. Re-derivable from the md doc's §9 appendix.
  • [SIM] — simulated: the 24-call trajectory itself. Grounded in [V] artifacts; turn counts are design targets. Its replacement is the measured Config 1/2/3 run (Sprints 1–3, seeds {0,1,2}).
  • [EST] — estimated: every duration. Anchored to the documented 60 min / 50 calls / 300 s; assumptions A1–A4 on slide 3 are the whole model. No public per-turn data exists for this harness — none was invented.

What would move the numbers

  • Slower turns (A1 violated): at 60 s/turn the total becomes ≈ 26 min — still 43% of budget. The design degrades gracefully.
  • Retries: one spec bounce or edit mismatch adds one turn (+15–45 s) per event; the rescue breaker caps the tail.
  • Cold pytest (A3 violated): first run +10–30 s; immaterial.
  • A bigger repo: read windows and subgraphs grow toward the 5k/10k caps — this task is near the friendly end.
