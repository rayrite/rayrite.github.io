How is the next call determined? Three policies, stated precisely [SIM] [R]

The decision engines

An agent choosing tool calls one at a time is acting in a POMDP: the true state (which code is wrong; what the hidden tests check) is hidden, tool outputs are partial observations, and a policy maps what the agent believes to its next action. Computing the optimal policy is intractable, so every practical agent runs a heuristic. The three agents in this deck run three different ones.

naiveReactive, salience-greedy

  1. Next action = a response to the most recent observation. Red test → read the failing test → undo. Big grep → shrink the grep.
  2. Belief lives only in the context window. Compaction or a long output can erase it, so the agent re-asks (N27).
  3. Stopping rule: budget pressure plus a green suite. The suite it trusts here is exactly the one that lies.
  4. Implicit inference rules, all usually right: the regression heuristic; “green ⇒ fine”; “smaller diff ⇒ safer”.

Cost on this task: 40 charged calls, 7 repeats, 2 reverts, a winning patch discarded.

BCFStructured heuristic: five ordered questions

  1. Which phase am I in? Spec / localize / patch / validate. The phase is a permission set (G0 locks file tools until the spec is valid).
  2. What is the next unmet obligation? An explicit checklist: unconfirmed hypotheses, the next DAG node, the next gate.
  3. Can I afford it? Budget plan: localize ≤ 10, force-submit at turn 42, rescue on 3 strikes or 25% budget.
  4. Have I tried this and failed? Journal lookup: no repeat of a failed action.
  5. Is there a cheaper tool for the same question? Graph → grep → read, smallest window first.

Stopping rule: gate vector all-true ⇔ submit. Cost here: 28 charged, 0 reverts, 3 near-zero graph calls.

Tier-2Calibrated and instrumented

  1. Same five questions, but question 5 ranks by p/C (expected payoff per cost) rather than cost alone, with search before graph (H4).
  2. Question 2's checklist gains provenance and closure obligations (H5, H6).
  3. Every red test passes through an asymmetry detector before any decision is made (H1).
  4. Commands are shaped so decisive lines survive the 5,000-char cap (H3); every edit batch gets a micro-check (H7).
  5. Every call's predictions and outcomes are logged (D1–D19), so the policy can be measured and later trained (H13).

Cost here: 20 charged, 0 reverts, 11/11 bullets.

◆ teachable moment: “heuristic” is a compliment A heuristic is a good-enough substitute for an optimum you cannot compute. Classical troubleshooting theory says that, under strong assumptions (one fault, independent checks), the optimal order is by decreasing pᵢ/Cᵢ: the probability a check finds the fault divided by its cost S2 S3. Greedy information gathering is provably near-optimal only when the problem has a diminishing-returns structure called adaptive submodularity S4, and plain greedy information gain can fail without extra conditions S5. BCF's ladder is a 1/C heuristic. Tier-2's is a p/C heuristic. Neither is optimal, and the replay shows exactly where the difference matters (Step 4).

◇ New terms in this step, defined at first use
POMDP S6
A partially observable Markov decision process ⟨S, A, T, R, Ω, O, γ⟩: states S, actions A, transition T(s′|s,a), reward R, observations Ω with likelihood O(o|s′,a), discount γ. The agent never observes s directly.
In plain words: Acting when you can only see clues, not the truth. Here: Hidden state = which code is wrong and what the hidden tests check; observations = tool outputs.
Belief state b S6
A probability distribution over S given the history; updated by Bayes: b′(s′) ∝ O(o|s′,a) Σ_s T(s′|s,a) b(s). It is a sufficient statistic for acting optimally.
In plain words: What you currently think is true, with confidence. Here: BCF writes its belief down (spec + journal); the naive agent's belief exists only in its context window.
Routing / classification gate
A deterministic map from issue text to a task template (here compat_or_refactor + feature sub-spec), computed before any repository access.
In plain words: Deciding what kind of problem this is before looking for it. Here: C1; the test-time rule allows issue text only.

◆ teachable moment: Issue-as-contract, tests-as-evidence Why forbid reading code before routing? Not for secrecy. The only artifact guaranteed to describe the graded behaviour is the issue text: the visible tests here are stale (Trap 1), and the code is wrong by definition (that is why there is an issue). The research literature calls the failure mode test overfitting: code that satisfies the observable tests but violates the specification S41 S48. Routing on the issue first is a cheap structural defence against it.

The measurement ceiling, and how to work under it

This section comes before the hypotheses on purpose. Every hypothesis in §15 has to be testable with the data you can afford, and the research pass computed what that data can resolve. The numbers are sobering, and they change what the hypotheses should measure.

ceilingResolve rate is a blunt instrument at n = 30

  • McNemar only counts disagreements. A +10 pp gain on 30 tasks is a net +3 tasks, and no split with a net of +3 is significant at any number of discordant pairs. The smallest significant results are 5–0 (mid-p) or 6–0 (exact) S133.
  • Minimum detectable effect at 30 tasks × 3 seeds, 80% power: about 17 pp in the central scenario (ICC 0.7, between-config correlation 0.8), and about 22 pp after Holm correction across 8 tests. Going from 3 to 10 seeds cannot push it below ~11 pp, because the number of tasks is the binding constraint S141.
  • Seeds are not tasks. With intraclass correlation 0.7, the 90 task×seed runs carry the information of only ~37 independent trials.
  • Published scaffold effects are mostly 2–9 pp (e.g. lint-on-edit +3.0 S18, reproduction-test selection +5.0 S14), well below the ceiling.
  • Run-to-run noise: SD above 1.5 pp even at temperature 0 on 500 tasks S151. On the 58-task public leaderboard, 0.20 / 0.22 / 0.24 are exactly 12 / 13 / 14 tasks, and their Wilson intervals overlap almost completely.

protocolWhat to do instead (H14)

  • Primary test: a paired t-test on the 30 task-level mean differences. It holds ≈ 5% false positives, where McNemar over the 90 pairs inflates to 6.6–12.4% when tasks respond differently to the configs (simulation, research pass).
  • Secondary: mid-p McNemar on a pre-registered majority-of-3 collapse; a task-level cluster bootstrap (BCa) CI.
  • Make mechanism endpoints primary. Per-call and per-edit rates (calls-to-localize, spec-reversion rate, proxy-test validity, residual references) have hundreds of events per arm. Analyse them with clustered standard errors, because events nest in runs nest in tasks.
  • Bundle compatible mechanisms into one arm when you need a resolve-rate effect large enough to see.
  • Pre-register the task list hash, seeds, endpoints, tests, α and the MDE sentence before the first candidate run. Report sub-MDE results as “could not distinguish effects smaller than ~17 pp; observed +X, CI [−Y, +Z]”, never as “no effect”.

Statistics for small evaluations

McNemar test S133 S134
Paired 2×2 table; discordant counts n₁₂ (A wins) and n₂₁ (B wins). χ² = (n₁₂ − n₂₁)² / (n₁₂ + n₂₁) ∼ χ²(1) under H₀. Exact form: n₁₂ ∼ Bin(n₁₂ + n₂₁, ½). Mid-p = exact two-sided p − f(n₁₂ | n).Plainly: Compare two agents on the same tasks by counting only the tasks where they disagree.In this deck: With 30 tasks, a net +3 tasks (+10 pp) is never significant; you need about 5–0 or 6–0.
Mid-p S133
For a discrete test statistic T, mid-p = P(T > t_obs) + ½ P(T = t_obs). For McNemar it never exceeded the nominal 5% in 9,595 scenarios while having more power than the exact test.Plainly: A fairer p-value for small counts.In this deck: Recommended secondary test (§13).
Statistical power / MDE S141
Power = P(reject H₀ | H₁ true). Minimum detectable effect δ = (z_{α/2} + z_β)·√[(ω² + σ²_A/K_A + σ²_B/K_B)/n] (Miller Eq. 10).Plainly: The chance your experiment notices a real effect / the smallest effect it reliably notices.In this deck: 30 tasks × 3 seeds: MDE ≈ 17 pp (≈ 22 pp after Holm over 8 tests).
Intraclass correlation ρ / design effect S141
ρ = σ²_task / (σ²_task + σ²_within). Kish design effect Deff = 1 + (m − 1)ρ; effective n = n·m / Deff.Plainly: How much the seeds of one task resemble each other.In this deck: At ρ = 0.7, 90 seed-runs carry the information of ≈ 37 independent trials.
Clustered standard error S141
SE_cl = [SE²_CLT + (1/n²) Σ_c Σ_i Σ_{j≠i} (s_ic − s̄)(s_jc − s̄)]^{1/2} (Miller Eq. 4).Plainly: Error bars that admit the seeds of one task aren't independent.In this deck: Required for every per-turn endpoint (edits nested in runs nested in tasks).
Cluster bootstrap / BCa S149 S141
Resample whole tasks with replacement (keeping their seeds together), recompute the statistic B ≥ 2,000 times. BCa adjusts the percentile endpoints by bias ẑ₀ = Φ⁻¹(#{θ̂* < θ̂}/B) and acceleration â (jackknife).Plainly: Simulate “another 30 tasks like these” from the data itself.In this deck: Secondary CI for the paired difference.
Wilson score interval S145
[p̂ + z²/2n ± z√(p̂(1−p̂)/n + z²/4n²)] / (1 + z²/n).Plainly: A proportion's confidence interval that behaves at small n.In this deck: 12/30 = 40% → (24.6%, 57.7%).
Holm / Benjamini–Hochberg S163 S164
Holm: sort p₍ᵢ₎ and reject while p₍ᵢ₎ ≤ α/(m − i + 1) (controls family-wise error). BH: reject p₍₁₎..p₍ₖ₎ for the largest k with p₍ₖ₎ ≤ kα/m (controls false discovery rate).Plainly: Corrections for testing many hypotheses at once.In this deck: 15 hypotheses in §12: one primary per batch, Holm within confirmatory families.
Brier score / log loss / ECE S172 S171
BS = (1/N) Σ (fᵢ − oᵢ)²; LL = −(1/N) Σ [oᵢ ln fᵢ + (1 − oᵢ) ln(1 − fᵢ)]; ECE = Σ_m (|B_m|/n)·|acc(B_m) − conf(B_m)|.Plainly: Scores for how honest a probability forecast is.In this deck: H4 scores the agent's logged p_hit predictions with these.

Machine learning, fine-tuning, LoRA and parameters

Parameters (weights) θ S90
The learnable tensors of a model, e.g. W ∈ ℝ^{d×k} per linear layer; “31B” counts ~31 × 10⁹ scalars.Plainly: The numbers training changes.In this deck: Frozen in every BCF config; H13 trains a small add-on (LoRA) instead.
Next-token loss (cross-entropy) S95
L(θ) = −(1/T) Σₜ log p_θ(xₜ | x_{Plainly: How surprised the model is by the right next token, averaged.In this deck: SFT/RFT minimize it on the assistant (action) tokens of successful trajectories.
Gradient descent, learning rate, epoch, batch S95 S91
θ ← θ − η ∇_θ L(θ); η = learning rate; an epoch is one pass over the data; a batch is the examples per gradient estimate. AdamW keeps per-parameter moment estimates.Plainly: Nudge the numbers downhill, a step of size η at a time.In this deck: LoRA prefers ~10× the full-FT learning rate (≈ 2e-4–5e-4 for code).
Fine-tuning / SFT S97
Continued gradient training of a pretrained model on a narrower dataset; SFT = next-token loss on (prompt → target) demonstrations, typically masked to the target tokens.Plainly: Teach a trained model a specific behaviour by example.In this deck: The candidate demonstrations are BCF's own resolved trajectories (D15).
PEFT S93
Parameter-efficient fine-tuning: train a small set of new or selected parameters while freezing the base weights.Plainly: Fine-tune by adding a small module instead of changing the whole model.In this deck: The competition's sanctioned adaptation path: adapters served by vLLM multi-LoRA (§3.4).
LoRA S90
Freeze W₀ ∈ ℝ^{d×k}; learn ΔW = BA with B ∈ ℝ^{d×r}, A ∈ ℝ^{r×k}, r ≪ min(d, k); h = W₀x + (α/r)·BAx. A is Gaussian-initialized and B = 0, so ΔW = 0 at the start. Mergeable, so it adds no inference latency.Plainly: Learn a thin “correction” to each weight matrix instead of the matrix itself.In this deck: Up to ~10,000× fewer trainable parameters than full FT of GPT-3 175B (Hu et al.).
Rank r, α, target modules S91 S93 S130
r = inner dimension of BA; α = scaling numerator (effective scale α/r; rsLoRA uses α/√r); target modules = which linear layers get adapters (q, k, v, o, gate, up, down).Plainly: How many independent directions of change the adapter can express.In this deck: vLLM here allows max_lora_rank = 128; Biderman et al. found r = 16–64 “tend not to suffice for code”.
Quantization / W4A16 S98
Represent weights (W) or activations (A) at reduced precision; W4A16 = 4-bit integer weights (here symmetric, group size 32) with 16-bit activations.Plainly: Store the model's numbers more coarsely to save memory.In this deck: The competition model is gemma-4-31b-it-qat-w4a16-ct.
QAT vs PTQ S99 S100
Post-training quantization (PTQ) quantizes a trained model; quantization-aware training (QAT) simulates quantization in the forward pass (straight-through estimator) so weights adapt to it.Plainly: Rounding after training vs practising with rounding during training.In this deck: Google did QAT; you would train adapters afterwards (H13).
NF4 / double quantization S92
NF4: 4-bit quantile quantization to the quantiles of N(0, 1) after rescaling to [−1, 1]. Double quantization quantizes the FP32 scale constants to FP8, cutting overhead from 0.5 to 0.127 bits per parameter.Plainly: A 4-bit format shaped like typical weight distributions.In this deck: Used by QLoRA training, not by the w4a16 serving format: a mismatch H13 measures.
QLoRA S92
Backpropagate through a frozen 4-bit (NF4) base into LoRA adapters: Y = X·dequant(W^NF4) + X·L₁L₂, with gradients for L₁, L₂ only; plus paged optimizers.Plainly: Fine-tune a big model's adapters on a small GPU budget.In this deck: 65B fine-tuning fits in <48 GB (Dettmers et al.).
Rejection-sampling fine-tuning (RFT) S63 S21
Sample attempts → keep only those a verifier accepts → SFT on the kept attempts → optionally iterate. Also called filtered behaviour cloning or expert iteration.Plainly: Learn only from your own (or a teacher's) successes.In this deck: H13's engine: Container-B-resolved trajectories, capped at 2–3 per task.
DPO S107
Minimize −E log σ(β log[π_θ(y_w|x)/π_ref(y_w|x)] − β log[π_θ(y_l|x)/π_ref(y_l|x)]) over preference pairs (winner y_w, loser y_l).Plainly: Learn from pairs: this answer is better than that one.In this deck: A candidate follow-up: paired (C9-style keep, N13-style revert) decisions.
GRPO S112 S121
Per prompt, sample G outputs; advantage Âᵢ = (rᵢ − mean(r)) / std(r) for all tokens of output i; PPO-style clipped objective minus β·D_KL[π_θ ‖ π_ref]; no value network. Dr. GRPO drops the std and 1/|o| terms.Plainly: Reinforcement learning that grades each attempt relative to its siblings.In this deck: Not scheduled; the natural step after RFT plateaus.
KL divergence penalty S112 S91
D_KL(π_θ ‖ π_ref) = E_{π_θ}[log π_θ − log π_ref]; subtracted (×β) to keep a tuned policy near its reference.Plainly: A leash that keeps the tuned model close to the original.In this deck: LoRA's low rank acts partly like such a leash (Biderman et al.).
Catastrophic forgetting / EWC S122 S123
Training on task B degrades task A. EWC adds Σᵢ (λ/2) Fᵢ (θᵢ − θ*_{A,i})², with Fᵢ the diagonal Fisher information.Plainly: Learning the new thing erases the old thing.In this deck: H13 includes a non-SWE canary set and a small general-data mix.
Overfitting / validation split S95
A widening gap between training and held-out error; a validation split is a held-out subset of training data for model selection, distinct from the test set.Plainly: Memorizing the examples instead of learning the skill.In this deck: The 30-task evaluation set must be disjoint from RFT training tasks.
Temperature / top-k / top-p S113
pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T); top-k keeps the k most likely tokens; top-p keeps the smallest set whose probability mass ≥ p.Plainly: Dials for how adventurous the model's next-token choice is.In this deck: Server default T = 1.0, top-p 0.95, top-k 64 (project notes); self-consistency needs T > 0.
Context window / compaction S29
The maximum tokens (prompt + history + output) the model attends to: here 32,768. ADK compaction summarizes older events once ~14,336 tokens are reached (§7.2).Plainly: The model's working memory, and what happens when it fills up.In this deck: Both trajectories cross the compaction trigger; the spec and journal must survive it (H10).
