## 3. Deep Dive into the 8 Universal Traps

### 3.1. TRAP-1: Visible Suite Contradicts Graded Suite (45 Tasks, 35.16%)
* **The Trap:** When an issue requires renaming an API, deprecating a parameter, or updating error classifications, the benchmark maintainers updated existing tests inside `test_patch` (e.g. deleting `- assert r.url == "http://example.com/foo"` and replacing it with `+ assert r.url == "http://example.com//foo"` in `requests_7315`). However, the agent's initial local workspace contains the **unpatched visible tests**.
* **Why Agents Fail:** If an agent writes the correct fix and runs `pytest`, the visible tests fail because they assert the old, buggy behavior! Standard agent prompts instruct the model: *"If tests break, your fix introduced a regression; undo it."* The agent enters an autoregressive loop undoing its valid patch.
* **Flagship Tasks:** `requests_7315` (preserving leading slashes in URL path), `fastapi_14964` (deprecating `ORJSONResponse`), `fastapi_14479` (changing `AssertionError` to `FastAPIError`), `rich_4070` (deferring startup imports).
* **BCF Brain Countermeasure:** **Non-Destructive Backwards-Compatible Aliasing & Dual-Mode Return**. When an API is renamed or deprecated, preserve the legacy symbol as an alias pointing to the new implementation (`complete = reset`).

### 3.2. TRAP-2: Twin-Tree & Tutorial Synchronization (18 Tasks, 14.06%)
* **The Trap:** In `fastapi/fastapi`, documentation examples under `docs_src/` are not static markdown snippets; they are fully executable Python files tested by `tests/test_tutorial/`. In 18 benchmark tasks, fixing a framework feature requires updating both the core engine (`fastapi/routing.py`, `fastapi/sse.py`, `fastapi/applications.py`) and the corresponding tutorial files in `docs_src/`.
* **Why Agents Fail:** The AST graph tool only connects symbols inside `fastapi/`. If an agent edits `fastapi/applications.py` but fails to update `docs_src/server_sent_events/tutorial001_py310.py`, the test suite fails on `test_tutorial`.
* **Flagship Tasks:** `fastapi_15030` (Server-Sent Events), `fastapi_14962` (Rust Pydantic JSON fast-path), `fastapi_15280` (`@app.vibe()`), `fastapi_14978` (`strict_content_type`).
* **BCF Brain Countermeasure:** **Subsystem Path Cross-Referencing**. Whenever a patch touches `fastapi/routing.py` or `fastapi/applications.py`, BCF triggers an automatic glob search across `docs_src/` for matching tutorial files.

### 3.3. TRAP-3: Latent Call-Site & Dynamic Proxy Faults (28 Tasks, 21.88%)
* **The Trap:** In `psf/requests`, Python file wrappers like `tempfile._TemporaryFileWrapper` delegate methods dynamically via `__getattr__` rather than defining them on the class. Standard type introspection using `isinstance(data, typing.SupportsRead)` or `isinstance(data, collections.abc.Iterable)` evaluates to `False` at runtime!
* **Why Agents Fail:** Models trained on standard type hints instinctively use `isinstance(data, ...)` or import `typing` protocols. This produces silent regressions where streamed file uploads are misidentified as raw strings or form dicts, leading to corrupted payloads or `TypeError`.
* **Flagship Tasks:** `requests_7433` (stream detection for `__getattr__` wrappers), `requests_7502` (`_encode_files` file wrapper detection), `requests_7505` (`hasattr` protocol checks across `models.py` and `_types.py`).
* **BCF Brain Countermeasure:** **BCF Dynamic Hasattr Guard (`DC-02`)**. In proxy and streaming environments, replace `isinstance(obj, Protocol)` with duck-typing guards: `hasattr(obj, "read")` or `hasattr(obj, "__iter__")`.

### 3.4. TRAP-4: Opaque Prompts, Red Herrings & Ungraded Bullets (34 Tasks, 26.56%)
* **The Trap:** 29 tasks have prompt length $<180$ characters (`PC-5`), such as `Fixes #3417` or bare PR titles like `proxy isatty` or `Inline table code`. Furthermore, several tasks include elaborate 5-bullet issue descriptions where the grading harness only runs 1 test file covering a single bullet.
* **Why Agents Fail:** In `PC-5` tasks, agents waste tool calls asking for more info or searching for non-existent keywords. In multi-bullet tasks, agents spend 80% of their turn budget fixing edge cases that yield zero points, exhausting the 6-minute task timeout before completing the core scored fix.
* **Flagship Tasks:** `rich_4077` (`proxy isatty`, 12 chars), `rich_4079` (`Inline table code`, 17 chars), `fastapi_15280` (bare title), `rich_3472` (Fixes #3417).
* **BCF Brain Countermeasure:** **Prompt Classification & Core Refactor Isolation (`SR-01`)**. On `PC-5` prompts, immediately query `git log -n 1 --oneline` and search target symbol names across `tests/` before exploring source code. On multi-bullet prompts, prioritize explicit renames and interface signatures first.

### 3.5. TRAP-5: Hidden Generators, Build Scripts & Compilers (8 Tasks, 6.25%)
* **The Trap:** In `Textualize/rich`, Unicode character width and grapheme tables are not hand-coded; they are generated by automated scripts that parse the Unicode Character Database (UCD). In `rich_3930`, the PR adds 23 separate Unicode version tables (`rich/_unicode_data/unicode4-1-0.py` through `unicode17-0-0.py`), totaling over 4,000 lines of generated code.
* **Why Agents Fail:** If an agent attempts to edit generated lookup tables directly, it risks syntax errors or table desynchronization.
* **Flagship Tasks:** `rich_3930` (Unicode grapheme cluster data), `fastapi_15661` (release automation script), `rich_3953` (Unicode binary search table).
* **BCF Brain Countermeasure:** **Generated Data Isolation & Table Invariant Check (`SR-11`)**. Detect generated module headers and restrict edits to the algorithmic consumer (`rich/cells.py`) rather than the static tables.

### 3.6. TRAP-6: AST Call-Graph Blindness (15 Tasks, 11.72%)
* **The Trap:** The precomputed call graphs provided in the competition data (`graphs/*.json`) were generated by a static AST parser that only creates nodes for top-level classes and functions. Module-level expressions, constants (`rich/_export_format.py`), `async def` routines (`httpx`), and net-new files (`fastapi_15661`) have **zero graph nodes**.
* **Why Agents Fail:** An agent that relies exclusively on `get_code_neighbors` or `get_code_subgraph` receives empty responses and concludes the symbol does not exist in the repository.
* **Flagship Tasks:** `fastapi_15661` (`GRAPH-4`, net-new script), `rich_3105` (`GRAPH-3`, export template constant), `fastapi_14791` (`GRAPH-2`, module-level router mounting).
* **BCF Brain Countermeasure:** **Dual-Engine Code Search (`SR-04`)**. Always run ripgrep (`rg -n`) in parallel with AST queries. If an AST tool returns zero edges, immediately fall back to text-based symbol localization.

### 3.7. TRAP-7: Tool Serialization & Backend Parser Freezes (100% of Tasks Affected)
* **The Trap (From Latest 2026-11-05 Intel):**
  1. **`edit_file` Backtick Swallowing (#756051):** When replacement code contains backticks or newlines, the argument parser swallows `,old_string:` into `new_string`, turning the next code line into a JSON key. Gemma 4 copies its previous broken output 51 times until the turn budget is exhausted.
  2. **vLLM 0.19.1 Server Freeze (#753973):** If a tool call emits an array argument (`list[str]`) containing a closing bracket `]` without proprietary `<|"|>` delimiters (e.g. `args:["Optional[int]"]`), the vLLM API server enters an infinite loop, memory reaches 26.7 GB, and all subsequent tasks in the run score 0.00.
  3. **150-Line `read_file` Silent Cap (#755291):** `read_file` silently truncates after 150 lines without warning. On `fastapi/params.py` (754 lines), naive agents read the first 150 lines 6 times without ever seeing the bug.
* **BCF Brain Countermeasure:**
  - **Single-Argument Heredoc Editor**: Ban multi-string `edit_file`; use raw heredoc patch application.
  - **Flat Scalar Tool Schemas**: Ban `list[...]` arguments in all tool definitions exposed to Gemma 4.
  - **Mandatory Line-Bounded Reading**: Require explicit `start_line` and `end_line` parameters on every read operation.

### 2.1. Flagship Breakdown: `requests_7433` | `__getattr__` Stream Detection vs `isinstance`

#### TLDR & Benchmark Engineering Perspective (Devil's Advocate)
`requests_7433` exposes a classic Python dynamic wrapper trap. In standard Python, file-like wrappers (such as `tempfile._TemporaryFileWrapper` or cloud storage client wrappers) do not inherit from `typing.SupportsRead` or `collections.abc.Iterable`. Instead, they forward unknown attribute lookups to an internal file handle using `__getattr__`. When Requests checks `isinstance(data, Iterable)`, Python inspects the wrapper class type dictionary and returns `False`! #### Capsule 1: `issue` | The Problem Statement Forensics
* **Prompt Length & Text:** 498 characters:

  ```

* **Forensics:** The prompt clearly explains the problem, but naively changing `isinstance(data, (Iterable, ...))` to `hasattr(data, "__iter__")` introduces subtle regressions if `data` is a dictionary or string!

#### Capsule 2: `code` | Latent Fault & Base Snapshot
* **Target File & Line:** `src/requests/models.py:512`
* **Base Snapshot:**

      hasattr(data, "__iter__"),

  ])
  ```
* **The Fault:** In `prepare_body`, Requests used `isinstance(data, (collections.abc.Iterable, ...))` to detect streamed upload bodies. For dynamic file wrappers, `isinstance` returned `False`, disabling chunked transfer encoding and crashing on large file uploads.

* **Trap 3 [V] | Dynamic Proxy Introspection:** The solution requires duck-typing via `hasattr(data, "__iter__")` while explicitly preserving exclusions for `(str, bytes, bytearray, list, tuple, Mapping)`.

## 1. Executive Summary & Architecture Upgrades

The exhaustive diagnostic breakdown of all 128 remaining benchmark issues in the Kaggle Google Gemma 4 Developer Agent competition taxonomy exposes critical systemic failure modes that plague standard LLM coding agents. Standard agents fail not because they cannot write Python code, but because:
1. They treat visible test suites as absolute ground truth, reverting valid fixes when visible tests assert obsolete behavior (`TRAP-1`).
2. They fall into tool serialization backtick swallowing loops (`TRAP-7`, #756051).
3. They emit array arguments that freeze the vLLM 0.19.1 async event loop (`TRAP-7`, #753973).
4. They waste 76% of their compute budget echoing files and reading the first 150 lines repeatedly (`TRAP-7`, #755291).
5. They spend 15 minutes attempting to solve mathematically impossible sandbox tasks (`TRAP-8`, #755554, #754586).

To neutralize these traps, this deliverable formally incorporates **6 New Declarative Pattern Cards (`DC-11` through `DC-16`)**, **6 New Strategic Rules (`SR-09` through `SR-14`)**, and an **Upgraded Triage Routing Engine** into the BCF "Brain".

## 2. New BCF Declarative Pattern Cards (`DC-11` through `DC-16`)

### 2.1. Card `DC-11`: Non-Destructive Alias & Dual-Mode Return Protocol
* **Target Trap:** `TRAP-1` (Visible Suite Contradicts Graded Suite — 45 Tasks)
* **Problem Addressed:** When an issue requires renaming a method (e.g. `complete` $
ightarrow$ `reset` in `httpx_3672`), deprecating a class (`ORJSONResponse` in `fastapi_14964`), or altering return types, the hidden `test_patch` asserts the new API name, but the local workspace test suite still asserts the old name. Deleting the old name turns visible tests red, prompting naive agents to undo their fix.
* **Declarative Template:**
  ```python
  class TargetComponent:
      def new_method_name(self, *args, **kwargs) -> Any:
          # True fix logic here
          ...

      # Backward-compatible alias satisfies visible local tests
      legacy_method_name = new_method_name

      def __getattr__(self, name: str) -> Any:
          if name == "legacy_property":
              warnings.warn("legacy_property is deprecated, use new_property", DeprecationWarning, stacklevel=2)
              return self.new_property
          raise AttributeError(f"{self.__class__.__name__} has no attribute '{name}'")
  ```
* **Operational Invariant:** Never delete a renamed public symbol during a refactor; always assign `legacy_symbol = new_symbol` as an alias.

### 2.2. Card `DC-12`: Dynamic Proxy Introspection & Duck-Typing Guard
* **Target Trap:** `TRAP-3` (Dynamic Proxy & `__getattr__` Delegation — 28 Tasks)
* **Problem Addressed:** In `psf/requests` and other network libraries, file wrappers (`tempfile._TemporaryFileWrapper`, S3 streaming bodies) delegate `.read` and `.__iter__` dynamically via `__getattr__`. Rigid type checks like `isinstance(body, typing.SupportsRead)` or `isinstance(body, collections.abc.Iterable)` return `False` at runtime.
* **Declarative Template:**
  ```python
  def is_stream_payload(data: Any) -> bool:
      # Exclude standard sequence containers first
      if isinstance(data, (str, bytes, bytearray, list, tuple, dict, set)):
          return False
      # Duck-type check handles __getattr__ proxies
      return hasattr(data, "read") or hasattr(data, "__iter__")
  ```
* **Operational Invariant:** In streaming, IO, and mock testing subsystems, replace `isinstance(obj, Protocol)` with `hasattr(obj, method)`.

---

### 2.3. Card `DC-13`: Single-Argument Heredoc Patching Engine
* **Target Trap:** `TRAP-7` (`edit_file` Backtick Swallowing Loop — Issue #756051)
* **Problem Addressed:** Gemma 4's tool-call parser breaks when replacement text contains newlines or backticks, swallowing `,old_string:` into `new_string` and promoting source code into JSON keys. This locks the model in a 51-turn failure loop.
* **Declarative Template:**
  ```python
  # Tool schema exposed to Gemma 4:
  {
      "name": "apply_patch",
      "description": "Apply a unified diff or raw heredoc replacement to a target file",
      "parameters": {
          "type": "object",
          "properties": {
              "filepath": {"type": "string"},
              "patch_content": {"type": "string", "description": "Raw unified diff or file content"}
          },
          "required": ["filepath", "patch_content"]
      }
  }
  ```
* **Operational Invariant:** Never expose multi-string replacement tools (`filepath`, `old_string`, `new_string`) to Gemma 4. Use single-payload heredoc editors or line-indexed patchers `(filepath, start_line, end_line, content)`.

### 2.4. Card `DC-14`: Scalar-Only Tool Parameter Schema
* **Target Trap:** `TRAP-7` (vLLM 0.19.1 Server Freeze on Array Arguments — Issue #753973)
* **Problem Addressed:** Emitting array arguments (`list[str]`) containing a bare closing bracket `]` without Gemma proprietary delimiters freezes the vLLM API server permanently, consuming 26.7 GB RAM and terminating the entire scoring run with 0.00.
* **Declarative Template:**
  ```yaml
  # configs/tools.yaml (Sanitized Tool Definitions)
  tools:
    - name: execute_command
      parameters:
        type: object
        properties:
          command:
            type: string
            description: "Single shell command string (e.g., 'pytest tests/test_core.py -k test_foo')"
        required: [command]
  ```
* **Operational Invariant:** Zero array parameters (`type: array`) in any tool schema exposed to Gemma 4. All compound arguments must be serialized as single scalar strings.
