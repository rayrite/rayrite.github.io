The real task [R task JSON + RCA] · difficulty 4/5 (multi-file)

Five bullets, five defects, two trees

issueThe whole problem statement (243 chars)

Server connection handling.

* Add `HTTPParser.keep_alive`.
* Server... always read request to completion on keep alives.
* `HTTPParser.complete` -> `.reset`
* Close streams on server exit.
* Don't raise `KeyboardException` on server exit.

The issue says keep_alive; the gold implements is_keepalive(). It says KeyboardException (sic); the fix handles KeyboardInterrupt. No traceback, no file names — the agent must localize from prose. [R]

mechanismFive verified defects [R RCA]

  • 1 · reset never called. _server.py:92 runs self._parser.complete — a bare bound-method reference, no parentheses. Parser stays DONE; the next keep-alive request fails its state transition. Async twin does await self._parser.complete → TypeError (not awaitable).
  • 2 · no drain. handle_requests never reads a body the endpoint ignored → leftover bytes corrupt the next parse.
  • 3 · 500 path crashes. Response(code=500,…) but the code is positional (_pool.py:175) → the error path itself raises.
  • 4 · sockets leak. _network.py:163 self._streams = list[NetworkStream] (the GenericAlias, not a list); __exit__ closes only the listener → handler threads hang shutdown(wait=True).
  • 5 · Ctrl+C escapes. HTTPServer.wait loops sleep(1) with no KeyboardInterrupt guard.

fixThe reference fix (+57/−22, 7 files) [R]

Rename complete→reset()->bool in both packages (True=recycled, False=closed); add is_keepalive() = both flags and send_state != CLOSED. Pool/server callbacks _complete→_reset and actually call reset(). After each response: if is_keepalive(): stream.read() then _reset(). Response(500,…). Add NetworkStream.is_closed(), a real _streams list, track/prune/close on exit. wait() breaks on KeyboardInterrupt.

d4Why this is difficulty 4 [R index.json]

7 files across two mirrored trees (src/ahttpx async source-of-truth + src/httpx sync, generated by scripts/unasync). Every change must land twice; the rename has a dependency order (parser defines reset/is_keepalive before callers use them). Patch: ahttpx _parsers +10/−2, _pool +4/−4, _server +7/−4; httpx _network +11/−1, _parsers +10/−2, _pool +4/−4, _server +11/−5. Multi-file + twin + state-machine = d4.

The concepts, explained kindly [R]

Teachable moments

POMDP / belief state
partially-observable Markov decision process — act under uncertainty, seeing only observations (tool outputs), never the true stateYou see clues, never the truth. Winning = keeping a sharper belief than the other agent. Beliefs only in the context window can be summarised away; beliefs on disk survive.here: C writes spec + state to .git/bcf/* and paraphrases every result into one visible sentence; naive's beliefs evaporate.
Entropy / information gain
H = −Σ p(x)·log p(x); expected gain = E[H before] − E[H after]A number for "how many ways is my belief still wrong?" A call only pays if it could change your mind.here: naive's N5/N7 byte-identical re-reads have zero gain by construction — a predictable result can't change the next action. C's locate (0.213 s) collapses the candidate set to two files.
Value of information
the worth of evidence = how much it changes the optimal decisionInformation is only worth what it changes about what you do.here: naive's full-suite "127 passed" could never fail (no test covers the ungraded bullets) → zero value. The targeted test that could fail is the one that matters.
Localization
shrink the hypothesis space with cheap deterministic evidence before any expensive/uncertain actionNarrow first — grep → file → lines — then edit, never blind.here: C reads the exact region and copies a verbatim unique window; apply takes a line range. Naive re-reads and wanders.
DAG / topological order
a directed acyclic graph; a topological order lists every node after its dependencies"Callers use reset()" forces "parser first" — write callers first and the code can't run.here: the twin-tree rename is a dependency. v3 sorts fix_order in code; C reasons it from the spec's alt target + mechanism.
Test overfitting / expected-red
optimising for an evaluation that differs from the true objective (visible test vs spec)The visible suite encodes the old API; the correct rename turns it red. Trust the spec over a misleading local signal — but only when a written prediction says the red was expected.here: v3 pre-computes the 5 red lines; C's doctrine says "statement plus mechanism is the contract." Both refuse the revert; C is more exposed to a panicking model.
The ratchet
a one-way constraint: committed progress is never reverted; failures route forwardNever undo a justified, spec-mandated edit in a panic.here: naive N13 reverts the correct rename → fail. C's ratchet is a prompt sentence; v3's is an asymmetry detector labeling the red "EXPECTED by spec."
Provenance
the origin of an artifact — hand-maintained vs machine-generatedAsk where a file came from before editing it.here: src/httpx is generated by unasync from src/ahttpx — edit the source, mirror the copy. And every number on a slide has a provenance too: measured, executed, or scripted.
