Install the latest NVIDIA Windows Game Ready or Studio Driver (572+ / 580+ series) on Windows 11 only. WSL2 automatically bridges CUDA into Ubuntu via /usr/lib/wsl/lib. Installing nvidia-driver-* inside WSL2 overwrites libcuda.so and breaks GPU access.

Dual-Boot Step D1 • Inside Windows 11 Pro (Mandatory Safety Prep)
5–10 min

Why Decrypt (Turn Off) BitLocker Instead of Merely Suspending? Windows 11 Pro frequently enables BitLocker Device Encryption automatically. Suspending BitLocker (-rc 1) only pauses it for 1 reboot—subsequent GRUB/UEFI boot-order changes frequently trigger the blue BitLocker Recovery Key screen on every switch into Windows. On a brand-new NVMe Gen 5 PC, decrypting C: takes only 2–5 minutes and eliminates cross-OS lockouts permanently (you can always re-enable BitLocker later once dual-boot is stable).

Windows PowerShell (Run as Administrator)
# 1. Confirm UEFI firmware & GPT partition table (both MUST be true!)
Get-Disk | Select-Object Number, FriendlyName, PartitionStyle, @{N="SizeGB";E={[math]::Round($_.Size/1GB,1)}}
(Get-ComputerInfo).BiosFirmwareType   # Expect: Uefi

# 2. Check BitLocker status & SAVE your 48-digit recovery key BEFORE touching anything!
manage-bde -status C:
manage-bde -protectors -get C: | Out-File "$env:USERPROFILE\Desktop\BitLocker_Recovery_Key_BACKUP.txt"
# (Copy BitLocker_Recovery_Key_BACKUP.txt to a USB drive or verify it in account.microsoft.com/devices/recoverykey!)

# 3. Turn OFF BitLocker (cleanest for dual boot). Skip if already "Protection Off / 0.0% Encrypted".
manage-bde -off C:
# Poll until Percentage Encrypted reaches 0.0% and Conversion Status is "Fully Decrypted":
manage-bde -status C:

# 4. Disable Hibernation & Windows Fast Startup (removes hiberfil.sys & unlocks NTFS cleanly!)
powercfg.exe /hibernate off

Double-check Fast Startup in GUI: open Control Panel → Hardware and Sound → Power Options → Choose what the power buttons do → click Change settings that are currently unavailable → verify Turn on fast startup is unchecked (or gone because hibernation is off) → Save changes.

Dual-Boot Step D2 • Inside Windows 11 Pro
5–10 min
Golden Rule: Always Shrink NTFS Inside Windows 11 — Never Inside Linux!

Letting Windows shrink its own C:\ volume guarantees NTFS metadata, shadow copies, and volume bitmaps stay 100% healthy.

  1. Press Win + X → select Disk Management (or run diskmgmt.msc).
  2. Locate your main Windows (C:) NTFS partition on Disk 0.
  3. Right-click C: → click Shrink Volume... (wait 10–30 seconds while Windows queries shrinkable space).
  4. In Enter the amount of space to shrink in MB, type your target Linux size in megabytes:
    • 409600 = 400 GB (recommended baseline)
    • 512000 = 500 GB (comfortable for 31B + E4B + multiple local sweeps)
    • 614400 = 600 GB (heavy overnight LoRA / dataset experiments)
  5. Click Shrink. Confirm a black-bordered Unallocated block appears immediately to the right of C:. Do NOT format it or create a new Windows drive letter—leave it completely Unallocated!
Troubleshooting: Windows Disk Management Only Lets Me Shrink by a Few GB! ("Unmovable Files" Fix)

NTFS cannot shrink past fixed system files sitting near the end of the volume (pagefile.sys, hiberfil.sys, System Restore shadow copies, or $UsnJrnl). Clear them temporarily in 4 steps:

  1. Ensure hibernation is off: Admin PowerShell → powercfg.exe /hibernate off.
  2. Disable System Protection: Press Win → search Create a restore point → select C: → Configure → select Disable system protection → click Delete existing restore points → OK.
  3. Temporarily Disable Paging File: Search View advanced system settings → Performance Settings → Advanced tab → Virtual Memory Change... → uncheck Automatically manage... → select No paging file → click Set → OK.
  4. Reboot Windows 11 (mandatory so Windows unlocks and removes pagefile.sys), open diskmgmt.msc, and run Shrink Volume again! If a stubborn file still blocks shrinking, open Event Viewer → Windows Logs → Application and check Source Defrag (Event ID 259)—it names the exact file path blocking the shrink boundary.
  5. IMPORTANT — Immediately Re-Enable Virtual Memory After Shrinking! Go back to Virtual Memory → re-check Automatically manage paging file size for all drives → OK → Reboot! (Keep Hibernation/Fast Startup OFF for dual-boot safety.)

Fix the Dual-Boot Clock Drift Permanently: Windows assumes your motherboard RTC clock is Local Time while Linux assumes UTC—causing the clock to jump by your timezone offset every time you switch OS. Pick Method 1 (Recommended) next time you boot Windows 11 Pro:

Method 1 (Recommended — Run Once in Windows 11 Admin CMD to Make Windows Use UTC)
reg add "HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1 /f

Alternative (Method 2 — inside Zorin OS if you prefer leaving Windows registry untouched): timedatectl set-local-rtc 1 --adjust-system-clock.

Scenario A: A Windows 11 Update Made the PC Boot Straight Into Windows (GRUB Menu Disappeared!)

Windows Updates occasionally push Windows Boot Manager back to #1 in UEFI NVRAM. Your Zorin installation is completely safe—restore GRUB in 30 seconds via either method:

  • Fastest (MSI BIOS): Tap Del → Settings → Boot → UEFI Hard Disk Drive BBS Priorities → move ubuntu / zorin back to Boot Option #1 → Save & Exit (F10).
  • From Inside Windows 11 Admin CMD: Run bcdedit /set {bootmgr} path \EFI\ubuntu\shimx64.efi (or use \EFI\ubuntu\grubx64.efi if Secure Boot is disabled) and reboot.
Scenario B: How to Cleanly Uninstall Zorin OS 18 & Reclaim All 400–500 GB for Windows 11 Pro
  1. Enter MSI BIOS (Del) → set Windows Boot Manager back to Boot Option #1 → boot into Windows 11 Pro.
  2. Open Disk Management (diskmgmt.msc), locate the healthy unnamed Linux ext4 partition (400–500 GB—verify size carefully so you never delete EFI or WinRE!), right-click → Delete Volume → it turns back into black Unallocated space right beside C:\.
  3. Right-click Windows (C:) → click Extend Volume... to absorb all reclaimed space seamlessly back into C:\!
  4. (Optional ESP cleanup) From Windows Admin CMD, run mountvol S: /S, delete S:\EFI\ubuntu (and S:\EFI\zorin if present), then run mountvol S: /D so your EFI partition is 100% stock Windows 11 again.
