# Front Door & Unified Reader — Design Spec

Date: 2026-10-03 · Status: Approved design (pending spec review)
Decisions locked: scope = auto-discover + skip-list ("B"); architecture = data-driven portal +
central reader ("Approach 1"); visual direction = **Terminal Dark** playground preset.

## 1. Goals

1. A mobile-friendly, responsive landing page ("front door") cataloguing every site section with
   an executive summary, family classification, scale stats, and entry links.
2. A unified markdown reader sharing the same design shell, replacing 4 copy-pasted readers +
   1 divergent browser.
3. A reusable Python script (+ Windows batch launcher) that recursively rescans the document root
   and refreshes the portal data — idempotent, stdlib-only, safe.
4. A system-prompt document instructing a coding agent to run the script **and** author/refresh
   executive summaries to match current contents.

## Non-goals

- Modifying existing content apps (ph/, aws2/, bsh/index.html, …) — they keep their own internals;
  the portal only links to them.
- Migrating or deleting any content. Redirect stubs preserve all existing reader URLs.
- Extending the GitHub Actions workflow (possible future: run script on push).
- Light-theme parity work beyond a usable light mode (dark is the design's home).

## 2. Design tokens — "Terminal Dark" system

One stylesheet pattern (CSS custom properties) consumed by portal and reader. Dark-first.

```css
:root, :root[data-theme="dark"] {
  color-scheme: dark;
  --accent: hsl(158 72% 56%);
  --accent-hover: hsl(158 72% 64%);
  --accent-soft: hsl(158 72% 56% / 0.13);
  --bg: #0b0f14;  --bg2: #10151c;  --bg3: #161d26;
  --tx: #d7dee6;  --tx2: #8b98a5;
  --bd: #232c37;
  --radius: 6px;
  --pad: 10px; --gap: 10px; --cardpad: 12px;   /* compact density */
  --font-ui: 'Inter', -apple-system, 'Segoe UI', system-ui, sans-serif;
  --font-mono: ui-monospace, 'Cascadia Code', 'JetBrains Mono', Consolas, monospace;
  --fs: 14px;
  /* family accents — mono-derived from the accent hue */
  --fam-study: hsl(158 60% 58%);
  --fam-research: hsl(158 45% 66%);
  --fam-data: hsl(176 55% 52%);
  --fam-creative: hsl(138 62% 60%);
  --fam-library: hsl(158 70% 68%);
}
:root[data-theme="light"] {
  color-scheme: light;
  --accent: hsl(158 68% 32%);
  --accent-soft: hsl(158 68% 32% / 0.10);
  --bg: #f4f7f5; --bg2: #ffffff; --bg3: #e9efeb;
  --tx: #17211b; --tx2: #5b6a61;
  --bd: #dde5df;

```

- First visit: `prefers-color-scheme` sets the theme; toggle persists in `localStorage`
  (`rr-theme`). Both pages respect it.
- Typography: Inter (Google Fonts, weights 400/500/600/700 — matches existing house style);
  monospace stack for stats/meta/code/filenames.
- Cards: 1px `var(--bd)` border, no shadow, `translateY(-2px)` + border-color shift on hover.
- Breakpoints: 1 col <640px, 2 col ≥640, 3 col ≥1024, 4 col ≥1280. Touch targets ≥44px.
- Focus-visible rings, `prefers-reduced-motion` respected.

## 3. Landing page — portal (`index.html`)

Stable hand-written HTML/CSS/JS. Fetches `site-data/site.json` (cache-busted) at runtime and
renders. No framework, no build step.

Structure:
1. **Sticky compact header** (blurred backdrop): gradient `r` mark + "rayrite · lab bench &
   publishing hub" wordmark; search pill (`/` shortcut); theme toggle.
2. **Filter chip row** (horizontal scroll on mobile): All / Study / Research / Data / Creative /
   Library — chips carry their family dot color.
3. **Card grid**: per section — 4px family edge-bar, tinted icon chip + emoji glyph, title,
   family badge, 2–3 line summary, meta row (`N apps · N files · Mmm DD`), "Open →".
   Sections with >1 entry get an inline expander listing sub-entries (path + title + entry
   summary when present), max 10 shown then "+N more".
4. **Footer**: `generated by refresh_site.py · <timestamp> · N sections`.

Behavior:
- Search filters live across titles, summaries, entry titles; result count shown; chip filters
  AND with search; "Clear" appears when active.
- Sort control: Updated (default) / Name / Size.
- States: skeleton cards while fetching; error card with Retry + link to the GitHub repo root
  (readable even without site.json); empty-state on zero matches.
- Card click → section primary entry. Entry click → that entry. Middle-click/ctrl-click opens in
  new tab (real `<a>` elements).

Accessibility: cards are `<a>`-wrapped regions; chips are buttons with `aria-pressed`; search has
label; color contrast ≥4.5:1 for text (family accents used on tints ≥12% luminance backgrounds).

## 4. Unified reader (`reader/index.html`)

Query contract: `reader/?src=<items-folder-relative-to-repo-root>` e.g. `?src=cvx/kaggle/items`,
`?src=bsh/docs/index`. Also accepts `&file=<name>` to deep-link a document.

Keeps the proven pipeline from the current readers:
- Listing: `items/manifest.json` (both `{files:[{filename, originalPath}]}` and plain-array
  forms) → GitHub Contents API fallback (repo/host auto-detect, branch main→master→gh-pages).
- Rendering: marked.js (GFM, breaks) → DOMPurify sanitize → Prism highlight (js, python, java,
  csharp, sql, bash, json) — same CDN set as today.

Shell & features (superset; gaps closed):
- App shell in the shared design system: sticky header (wordmark = library path, file filter
  pill, theme toggle); left sidebar file list with active state and per-file word count; main
  ~72ch column; right TOC rail with scroll-spy (IntersectionObserver) on desktop, slide-in
  drawer + bottom thumb-zone bar (prev · TOC · next) on mobile.
- Thin reading-progress bar at the top.
- Prev/next document navigation (buttons + `←`/`→` keys) across the file list.
- Full-text search across the section's documents: lazy-fetches all `.md` once on first search
  (sequential, progress indicator), caches in memory; results list with snippets + highlight;
  click jumps to file (and to heading anchor when matched).
- Persisted preferences (`localStorage`, namespaced `rr-reader-*`): theme, font size, last file
  per library, scroll position per file (resume on return).
- Font-size control 12–24px; print stylesheet incl. Ctrl+P handling (inherited behavior).
- `.html` items (mdh's study pages): rendered in a sandboxed `<iframe>` inside the shell with
  the same header/sidebar; label chip "HTML document".
- Keyboard: `/` filter, `←`/`→` prev/next, `t` theme, `Esc` closes drawers, `Ctrl+P` print.
- Error states: file fetch error (retry), empty library, manifest+API both failing (guidance to
  serve over HTTP locally).

## 5. Redirect stubs (script-managed)

Each configured reader folder's current `index.html` viewer is replaced by a ~10-line stub:
`<meta http-equiv="refresh" content="0; url=/reader/?src=<items-folder>">` + JS
`location.replace` fallback + visible link. Script writes stubs only when content differs
(idempotent). Old copies are archived once, manually, to `docs/legacy/` during rollout
(see §10).

## 7. `refresh_site.py` (repo root; stdlib only)

1. Load `config.json` (create with defaults if missing). Flags: `--dry-run`, `--verbose`,
   `--root <path>` (defaults to script's parent).
2. Walk the tree (respecting `skip`/`skipFiles` glob rules).
3. Per top-level content folder: discover entries — child dirs containing `index.html`, searched
   up to 2 levels deep (covers `dukr/opensource/1/`) + section-root `*.html`; primary = section
   `index.html` if present else first entry. Titles from `<title>` (fallback: prettified folder name).
4. Classify family: config override → readerFolders membership (`library`) → keyword heuristics
   on titles (`exam|aws|study|quiz|glossary|certif` → study; `whitepaper|research|kaggle|corpus|plan|docs`
   → research; `viewer|browser|archive|watchlist|review|showcase|dashboard|catalog` → data;
   `demo|splash|anim|timeline|game|three|pixi|webgl|carousel` → creative) → default `data`.
5. Merge summaries (agent text wins; `summarySource` accordingly; heuristic = `<title>` + first
   meaningful text block ≤300 chars). Flag `needsSummary` / `staleSummary` (section
   `lastModified` > summary `basedOn`).
6. Write `site.json`; sync reader stubs; write `refresh-report.json`. Only files whose content
   changed are rewritten (byte-compare) → clean git diffs, safe to run repeatedly.
7. Console report mirrors refresh-report.json. Never deletes anything; reads text files with
   size caps (2MB) and encoding fallback (utf-8 → latin-1) for title extraction only.

## 8. `REFRESH_SITE.bat` (repo root)

```bat
@echo off
cd /d %~dp0
where py >nul 2>nul && (py -3 refresh_site.py --verbose) || (python refresh_site.py --verbose)
echo.
pause
```
Desktop icon: right-click the .bat → *Send to → Desktop (create shortcut)* (documented in the
agent prompt + README note in `docs/`).

## 9. `docs/REFRESH-SITE-AGENT-PROMPT.md` (agent system prompt)

Contents (sections): Role & objective; Preconditions (repo clean enough to diff); Step 1 run
`refresh_site.py --verbose` (or the .bat); Step 2 read `site-data/refresh-report.json`;
Step 3 for each `needsSummary`/`staleSummary` item: deep-read the section's entry documents,
write 2–3 sentence executive summaries (≤320 chars; cover topic, scale, tech; factual tone;
no marketing fluff; examples given for good/bad) into `summaries.json` with `basedOn` = section
`lastModified`; Step 4 re-run script; Step 5 verify `site.json` changed and `needsSummary` is
empty; Step 6 report diff summary + suggest commit message. Guardrails: modify only
`site-data/summaries.json` (and never `site.json` by hand); don't rename/move content; if a
section is unclear, mark summary `"text": ""` and note it in the report. Verification checklist
at the end.

## 10. Rollout plan

1. Seed `summaries.json` from the 2026-10-03 inventory (agent-quality summaries, all 23 sections).
2. Build portal `index.html`; rename current root `index.html` → `index-gallery-legacy.html`
   (relative image refs keep working).
3. Build `reader/index.html`; archive replaced viewer copies to `docs/legacy/` (e.g.
   `docs/legacy/md-index-2026-10-03.html`) before stubs overwrite them.
4. Add `refresh_site.py`, `REFRESH_SITE.bat`, config; run script; verify site.json + stubs.
5. Local verification over `python -m http.server 8000`: portal loads/data renders; mobile
   viewport (375px) check; each reader library loads incl. mdh HTML items; old URLs
   (`/md/`, `/scam/`, …) redirect into the reader; full-text search on cvx/kaggle.
6. Idempotency: run script twice → second run reports no changes.

## 11. Testing

- Script: `--dry-run` output equals real run's planned changes; idempotency (run ×2 → no diff);
  skip-list honored; rename-safety (no exceptions on odd filenames).
- Portal: fetch failure path (rename site.json temporarily); search/filter/sort; keyboard `/`;
  theme persistence.
- Reader: each library (md, md-dxc, scam, dukr/opensource/1, bsh/docs, cvx/*, mdh); prev/next;
  persisted prefs; print; search snippets; deep link `?src=…&file=…`.
- Cross-check: every path in site.json resolves (script emits warnings for dead links).
