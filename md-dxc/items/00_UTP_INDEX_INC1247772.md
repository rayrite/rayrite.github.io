# Unit Test Plan — Vietnam A01 OT Connect (INC1247772)

**Scope:** BR-01 (daily 4hr Overtime/Bank Time cap), BR-02 (daily 12hr total-hours cap), BR-03
(full-day Annual/Personal Leave blocks Overtime/Bank Time), and the implicit Public Holiday OT
prerequisite check, for Vietnam org `A01` only, as defined in
`docs_INC1247772/PATCH_PLAN_INC1247772_VIETNAM_A01_OT.md` and implemented in
`patched/PAYEDIT2A.SQL` / `PAYEDIT2C.SQL` / `PAYEDIT_PTA_2A.SQL` / `PAYEDIT_PTA_2C.SQL`
(procedure `vn_checks`). No changes were made to `UNIT_EDIT.bdy` or `TLS_TimeValidation.sql`
(Vietnam's codes are all hours-type, structurally unreachable in the unit-flagged routing path).

**Scripts:** all 17 tests are **standalone**, F5-runnable `.sql` files in this same folder
(`docs_INC1247772/UTP_INC1247772/T-1247772-A01-NNN.sql`) — each file fully inlines the CV-LCD-GVR
report body (worker info, leave balances, timesheet grid, simulation output table) with zero
external file dependencies. The report body is extracted **directly** from
`cvx_deluxe_harness/CVX_01_REGULAR_TIMESHEET_DELUXE_v2.sql` (the v2 standalone spec template —
see `cvx_deluxe_harness/README_v2_TEMPLATES.md`) by `gen_1247772_standalone.py`, which lives
alongside these scripts in this same folder; regenerate with:
```
cd docs_INC1247772/UTP_INC1247772 && python gen_1247772_standalone.py
```
Because the generator reads the body straight out of the v2 template file (not a cached copy),
these scripts are guaranteed to match the v2 spec byte-for-byte, including both bug fixes
documented there (no `lcd.worker.profile` reference; `l_contractor`/`l_long_day` sized
`VARCHAR2(100)`). Self-check performed on all 34 generated files (regular + PTA): no unresolved
`@@` includes, no undefined `&substitution` tokens, no reintroduced `l_profile` reference, no
undersized `VARCHAR2(20)` `l_contractor`/`l_long_day` locals, exactly 2 body variants across all
34 files (one per template, byte-identical within each group), exactly 2 `/` block terminators
and at least 2 `ROLLBACK;` statements per file.

**Harness:** `LCD.time_edits_validation`, `p_edit_type='I'`. Reason codes 86000300-86000303 come
from `validate → vn_checks`.

**Test employee used throughout:** org `A01` (Vietnam), worker `1118838` — a real, active worker
who appears in `tables/VIETNAM_A01_EMPS_LCD_1012.xlsx`, `_LCD_1013.xlsx`, and `_LCD_2900.xlsx`
(i.e. has historically used all three OT-family codes this ticket touches). Every test assumes
`worker_info.long_day` resolves to `8` for this worker (the standard Vietnam workday) — re-verify
against `lcd.worker_hist` before trusting any BR-03 (Check 302) result if this worker's actual
`long_day` differs.

**Week ending used throughout:** `v_week_end = '20260918'` (Friday — the nearest upcoming Friday
from 2026-09-13, today, per the playbook's Phase 4.3 date rule). Day-slot mapping: Sat=9/12,
Sun=9/13, Mon=9/14, Tue=9/15, Wed=9/16, Thu=9/17, Fri=9/18.

**How to run a test script:**
1. Open the script in SQL Developer.
2. Press **F5** (Run Script, not Ctrl+Enter) — no edits needed for the `A01` tests; test 017
   (org `111` regression) needs a real worker substituted for `REPLACE_ME` first.
3. Copy everything between the ` ```markdown ` fences, or just read the **Simulation Output**
   table and the **TEST VERDICT** banner at the bottom of the output.
4. Compare the findings against the **Expected Result** column below.

## PTA path — `T-1247772-PTA-A01-NNN.sql`

The same 17 scenarios are replayed through the PTA path (`LCD.time_edits_validation_pta` →
`PAYEDIT_PTA_2A.SQL` / `PAYEDIT_PTA_2C.SQL`, which received the identical `vn_checks` edits) as
`docs_INC1247772/UTP_INC1247772/T-1247772-PTA-A01-NNN.sql` (this same folder), generated by
`gen_1247772_pta_standalone.py` (also in this folder), which extracts the report body **directly**
from `cvx_deluxe_harness/CVX_02_PTA_TIMESHEET_DELUXE_v2.sql` — the v2 PTA spec template, CURRENT +
ORIGINAL timesheet grids, same week.

**PTA-specific configuration:**
- `v_week_end = '20260828'` (a Friday at least 14 days before 2026-09-13, per the playbook's
  Phase 4.3 PTA date rule). Day-slot mapping: Sat=8/22, Sun=8/23, Mon=8/24, Tue=8/25, Wed=8/26,
  Thu=8/27, Fri=8/28.
- `v_edit_type = 'C'` — the only edit type the production PTA path actually sends, unlike the
  regular-path tests above which use `'I'`.
- ORIGINAL (`b_array_*`) is set **identical** to CURRENT (`p_array_*`) in every test. This is a
  genuine no-op for **all four** of this ticket's checks, verified by tracing the actual PTA call
  graph (not just the `tally()`-vs-`ptally()` hook, which was the full extent of the equivalent
  check for INC1444350): the outer, PTA-aware `VALIDATE` overload calls the inner, CURRENT-only
  `VALIDATE` overload FIRST — which runs `tally()` and, at its own end, calls `vn_checks` — and
  only AFTER that inner call returns does the outer procedure run `ptally()` over ORIGINAL and
  call `calculate_deltas` (which is what overwrites `total_day`/`total_day_vac`/`total_day_ot`/
  `total_day_hol` with delta values, consumed by `leave_check`, not by `vn_checks`). So `vn_checks`
  always reads raw CURRENT-pass totals, in every one of the 4 patched files, regardless of what
  ORIGINAL contains. (This corrects an assumption from an earlier draft of the patch plan — see
  that document's section 2 for the full trace and the correction note.)

The ID/script/category/expected mapping is 1:1 with the regular-path table below — e.g.
`T-1247772-A01-010` (regular) and `T-1247772-PTA-A01-010` (PTA) exercise the exact same
8100+2000-same-day scenario, just through the two different call paths. See the table below for
the full scenario list; substitute `T-1247772-A01-` → `T-1247772-PTA-A01-` in the ID/filename
column to get the PTA equivalent of any row.

## Coverage summary

- Every one of the 4 new reason codes (86000300, 86000301, 86000302, 86000303) has all four
  categories (Interior/Exterior/Boundary/Edge) represented, both regular and PTA path (34 scripts
  total).
- Cross-org regression (test 017): confirms a non-Vietnam org entering the same numeric codes is
  entirely unaffected.
- Interaction coverage: test 006 confirms Check 300 and Check 301 are independent (1012 counts
  toward the 12hr total but not the 4hr OT/BankTime sub-cap); test 013 confirms Checks 301/303
  can coexist cleanly at the boundary (PH present, total exactly at the 12hr cap); test 011
  confirms Check 302's combined-leave-types trigger explicitly requested during Phase 1.
- No existing check was widened or extended by this patch (unlike the INC1444350 precedent's
  Check 286), so no "regression test for a widened existing check" category applies here — the
  cross-org regression (017) is this ticket's only non-BR-01/02/03/PH-prerequisite test.
